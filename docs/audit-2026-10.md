# BitStream audit — October 2026

Branch `audit-2026-10`, baseline `main` @ 69c0fef (v1.3.0).
Scope: (1) serious bugs, (2) SpecTalkZX/NetChessZX rendering and UART lessons,
(3) start of the Spectranext port.

## 1. Serious bugs found and fixed

| # | Area | Defect | Consequence | Fix |
|---|------|--------|-------------|-----|
| B1 | BPE expander (`main_puts`) | Bytes ≥0x80 were always taken as tokens with no bound; `ftp_path` (257 reply) was printed raw | Any non-ASCII path (`/música`) read past `bpe_dict`; nested garbage overran the 16-byte `bpe_rstack` → wild writes | Token must index inside `bpe_dict..bpe_dict_end`; depth capped (16 levels, build fails if the dictionary is deeper); every server text goes through `utf8_to_ascii` first |
| B2 | Download integrity | Success = seeing `1,CLOSED`; size never checked | Truncated/corrupt files reported "OK" | `received == SIZE` required; 4xx/5xx final reply = failure; partial file removed |
| B3 | Download start | Only `550/553/ERROR/Fail` recognised before data | `425/426/450/451/530` → 8 s silent wait, no message, nothing downloaded | Generic reply engine: any ≥400 reply is shown and aborts |
| B4 | 0-byte / tiny files | `1,CLOSED` arriving before the `150` was discarded by the start wait | Empty files timed out after 15 s and were deleted | Data EOF is a stream event, independent of the 150 |
| B5 | Reply parsing | `strstr(line,"250")` etc. over the whole line, including the `+IPD,0,<len>` field; only the first line of an IPD frame carried the prefix | False positives/negatives; multi-line replies (`230-`) lost or misread | `+IPD` demultiplexer; RFC 959 code parser (`ddd ` / `ddd-` multi-line) |
| B6 | CIPSEND prompt wait | Consumed and discarded every byte while looking for `>` | Socket payload (incl. the other link) lost; a stray `>` sent data too early | Prompt is an event of the demultiplexer; nothing is discarded; BREAK no longer abandons a CIPSEND half-way |
| B7 | UART TX (divMMC) | 256-poll timeout silently dropped the byte | AT/FTP commands sent with holes (protocol desync) | Bounded wait + fail-stop latch `uart_tx_failed`; transmit stops; `!INIT` clears it |
| B8 | UART RX (divMMC) | Drain ≈450 T/byte (ready+read calls, latch, DI/EI); a byte arrives every ≈304 T at 115200 | Drain could not keep up with bursts; relied on FIFO/flow control | Inline drain ≈155 T/byte, ring-free budget computed up front, ~1.3-byte-time tail poll; RX drained while TX is busy |
| B9 | Glyph LUT | `ALIGN 16` is not absolute in z80asm; lookup ignored the carry | Garbled text whenever `font_lut` landed at `$xxF7..$xxFF` (it did in the Spectranext build) | Carry-safe lookup; test sweeps the table across page ends |
| B10 | `utf8_to_ascii` | Lead bytes consumed following bytes without checking continuations | `caf\xE9.txt` → `caf?xt` | Continuation-validated decoder, Latin-1 fallback |
| B11 | Data socket/RETR command | (introduced and caught during this work) AT layer reused `tx_buffer` | — | Own `at_buffer` |
| B12 | Progress bar | `(received>>8)*16` in 16 bits | Wrong bar > 1 MB, truncated > 16 MB | Scaled 32-bit ratio |
| B13 | NAT/containers | PASV private address used verbatim | "Data connect failed" against NAT'd servers | Unroutable PASV address replaced by the control host |
| B14 | Leaked ESP links | Failed data connect / failed NOOP left link 0/1 open | Every later connect "ALREADY CONNECTED" | Links closed on failure; `!INIT` closes all |

Latent issues also fixed: `cache_row_y` not initialised; `main_print` fast path

## 2. Lessons ported from SpecTalkZX / NetChessZX

UART (divMMC/divTIESUS, `asm/divtiesus_uart.asm`): status-only readiness,
defensive read, no DI/EI, CF/A `uartRead` contract, fail-stop TX, RX-during-TX,
inline drain, transport-owned startup flush.

Rendering (`asm/bitstream_asm.asm`): scroll with interrupts enabled and
unrolled LDI (83.7 kT uncontended, ≈−20 % vs LDIR) after draining the UART;
`print_line64_fast` blank-pair fast path (−25 % vs per-char on mixed rows);
cached attribute base reuse; computed attribute rows (−48 B table); BPE bounds;
UTF-8 decoder; cursor shift shown only after it is stable for 3 frames and
only for a *clean* CAPS (not CAPS+digit/SPACE/SYM chords).

Not ported in this pass (size-only, BitStream now has ≈1.5 KB more stack
headroom): compact `in_inkey`, ASM `read_key`, ASM input redraw, word
navigation/wrap.

## 3. Spectranext port (started)

`include/bitstream_net.h` is the seam. `src/net_spectranext.c` drives the
cartridge ROM sockets through the SpectraNext driver bridge (`spxn_rom.asm`):
two BitStream-owned descriptors (control + PASV data), POLLFD-before-RECV,
ports 22/443 refused. `src/fs_spectranext.c`: XFS slot 0 pinned, create /
write / VCLOSE, commit after a verified download, unlink on failure.
`make spectranext SPXN_DIR=…/SpectraNext/driver`; manifests in
`packaging/spectranext/`.

Status: builds; in FuseX it boots (cart detected, Wi-Fi, XFS), logs in,
lists, runs CWD/PWD and downloads small files; files are committed and survive
in the XFS profile. Not yet run on the physical cartridge.

Two FuseX 1.9.2 emulator defects (not BitStream; both in
`peripherals/nic/w5100_socket.c` of the ZXESPEmu-built FuseX):

1. `w5100_socket_connect()` marks a plain TCP socket ESTABLISHED but wakes
   the I/O thread's `select()` only for SSH sockets, so no RX is seen until
   the guest sends something; server-speaks-first protocols (the FTP banner)
   hang. Fix: call `compat_socket_selfpipe_wake( self->selfpipe )`
   unconditionally at the end of the connect path.
   `-DBITSTREAM_SELFTEST_PROBE` sends a NOOP after connect to get past it in
   test builds only.
2. `w5100_socket_recv()` (the RECV command) only acts in ESTABLISHED/UDP
   states. Once the host side reports EOF the socket is CLOSE_WAIT and the
   data still buffered (up to 2 KB) is never delivered: observed as the last
   1 056 of 20 000 bytes and 589 of 61 517 bytes missing, and LIST cut after
   the first 256-byte RECV. A real W5100 allows RECV in CLOSE_WAIT. Fix: also
   accept `W5100_SOCKET_STATE_CLOSE_WAIT` there. BitStream's size check
   caught both truncations ("Size mismatch", file removed).

Open points for hardware: two simultaneous outbound TCP sockets (control +
data) are not yet proven on the cart; `$3EF0` op 0 IP byte order (FuseX gives
first octet first); behaviour of a blocking CONNECT to an unreachable PASV
address; commit time for large files.

## 4. Verification

- `make targets`: divTiesus 35 094 B, AY 35 683 B, Spectranext 32 747 B TAP.
  divTiesus BSS end $FC25 → $F660 (+1 477 B stack headroom).
- `tools/test_asm_cpu.py` (z88dk-ticks): glyph decode at any LUT address,
  UTF-8 cases, BPE bounds, LF path, ring copy, renderer equivalence, scroll
  geometry + IFF. The glyph test fails on the pre-fix code.
- `tools/e2e_zesarux.py` (ZEsarUX ZX-Uno UART + ZXESPEmu + pyftpdlib with a
  NAT'd PASV address): boot, banner, login, LIST through the pager, GET of
  104 B / 0 B / 61 517 B files (SHA-256 equal), 550 handling, `%`-escaped UTF-8
  directory + PWD folding, search, QUIT.
- Not covered: real divTIESUS FIFO timing, AY bit-bang UART, physical
  Spectranext.
